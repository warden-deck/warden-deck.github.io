Warden

A security-conscious Linux server workspace with monitoring, file management, a multi-file editor, Git source control, a real PTY terminal and structured administration behind one Go service.

Current status

Development build.

Warden is intended for local/private dogfooding while the adversarial security programme and deployment hardening continue. It already exposes meaningful authority: an authenticated user can write files, commit code and use a shell.

The interface is organised around distinct jobs rather than one dashboard that tries to do everything. Explorer handles broad file management; Editor owns project workspaces; Source Control exposes a bounded Git workflow; Terminal is the escape hatch to the real OS; Monitor and System provide typed views for common server operations.

Build and run

nift build
go test ./...
go build -o warden ./cmd/warden
./warden hash-password 'choose-a-strong-password'
export WARDEN_PASSWORD_HASH='pbkdf2-sha256$...'
./warden

Nift builds the frontend into public/. Runtime behavior remains ordinary browser JavaScript talking to the Go API. The default listener is 127.0.0.1:8080.

Know the authority boundary

WARDEN_FILE_ROOT confines filesystem APIs. It does not sandbox the terminal. Git source control is deliberately limited to the explicitly opened workspace root, while the PTY runs with the Warden process user's normal OS authority.

Read Security before exposing Warden beyond a trusted environment.
