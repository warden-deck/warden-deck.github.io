Security

Warden is intentionally powerful, so security is defined by server-side boundaries and operating-system authority rather than by which controls happen to be visible.

Implemented controls

  • persistent server-side 12-hour sessions with HttpOnly, SameSite=Strict cookies;
  • per-session CSRF tokens for state-changing HTTP requests;
  • login rate limiting by client address, with explicit trusted-proxy support;
  • optional per-password-identity TOTP with one-time recovery codes;
  • AES-GCM encrypted storage for recoverable secrets;
  • same-origin checks plus authentication/CSRF for terminal WebSockets;
  • restrictive CSP, frame, referrer and content-type headers;
  • filesystem confinement with symlink resolution;
  • atomic editor writes and permission preservation;
  • structured administrative actions rather than arbitrary command strings;
  • privileged activity appended to a mode-0600 audit log.

Destructive account and instance-reset operations require the acting administrator to re-enter a Warden password in a masked browser field; a confirmation click alone is not sufficient.

Current deployment position

Private dogfooding while the multi-user boundary is being hardened.

Warden now has persistent account sessions, role/capability enforcement, TOTP, optional Google login, encrypted secrets, session management and identity-aware auditing. It is still powerful server software and should be deployed deliberately rather than treated as an untrusted-user sandbox.

Prefer HTTPS for remote use. When a reverse proxy supplies the public client address, enable trust_proxy; Warden will then use trusted X-Forwarded-For/X-Real-IP values for audit/rate-limit identity. With proxy trust disabled, forwarding headers are ignored, and their presence prevents a request from being treated as a safe loopback first-run setup request.

Terminal authority

The PTY is the largest capability boundary. If an authenticated visitor should not receive a shell as the Warden OS user, they should not receive terminal-enabled Warden access either.
