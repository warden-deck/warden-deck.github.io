Coding agent

Warden Agent runs OpenCode inside Warden-managed workspaces while Warden retains control of account identity, credentials, workspace confinement, audit and usage attribution.

Provider selection

Agent sessions can use any supported provider configured in System → AI providers: OpenCode Zen, OpenRouter, OpenAI, Anthropic, Google Gemini, DeepSeek or local Ollama. The provider dropdown belongs to the current agent session, so two sessions can use different providers at the same time. Warden uses the provider’s configured default model and passes the resulting provider/model reference to OpenCode.

Credentials and multi-user boundaries

API-key providers use Warden’s normal personal-override/shared-company credential policy. The resolved key is injected only into that isolated OpenCode process and is never returned to the browser. Ollama does not require an API key.

Warden deliberately does not reuse a single host-level ChatGPT or GitHub Copilot OAuth login for every Warden account. That would collapse Warden’s per-account credential boundary. Subscription OAuth can be added later with account-scoped authorization rather than silently sharing one operating-system credential between users.

Sessions

The ＋⌄ menu separates New session from New workspace. New session starts a fresh OpenCode conversation in the current agent workspace. New workspace starts a separate session and asks for another directory. Recently closed sessions can be restored from the same menu.

Open sessions and recently closed sessions are stored per Warden account in the browser. Each session also receives a persistent, account-scoped OpenCode data directory under Warden’s private configuration directory, so a restored session can continue the same OpenCode conversation rather than merely recreating its transcript.

Visible execution

Assistant text, tool calls, commands, completion states and errors stream into both the dedicated Agent view and the integrated Editor agent pane. Whitespace-only events are discarded, tool status is highlighted, and Copy session copies the visible conversation and tool trace.

Usage accounting

Warden reads usage from OpenCode’s streamed events and also exports the successful OpenCode session after each run. The export path recovers token and cost data from OpenCode’s persisted tokens.input, tokens.output and cost fields when the final headless event is missing. Provider usage remains attributed to the Warden account that launched the task.

Recovery

Some OpenCode releases can finish run --format json successfully without emitting the final assistant text or final usage event to stdout. Warden captures the session ID and exports that isolated session after completion, recovering missing assistant output and accounting data instead of presenting an empty or misleading success.

Authority

The agent works only inside a workspace path accepted by Warden’s configured filesystem root. OpenCode can read and edit files and run commands there, so agent.run is a high-authority capability. Like Terminal access, commands ultimately execute with the operating-system authority of the account running this Warden instance.
