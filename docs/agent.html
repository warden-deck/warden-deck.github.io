Coding agent

Warden Agent runs a real coding agent inside the Editor workspace while Warden retains control of identity, credentials, workspace confinement, audit and usage attribution.

First implementation

The first dogfood implementation uses DeepSeek V4 Flash through OpenCode and OpenCode Zen. OpenCode runs non-interactively with its JSON event stream; Warden renders progress and model/tool output in the Agent view and refreshes the workspace and Source Control when the run finishes.

Warden account
  → agent.run capability
  → open Editor workspace
  → resolved OpenCode Zen credential
  → isolated OpenCode process
  → DeepSeek V4 Flash

Configure the credential

In System → AI providers, store an OpenCode Zen API key as either the account credential or shared/company credential. An OpenRouter key is a different credential and is not used by this integration.

Credential and process isolation

Warden resolves the OpenCode Zen credential using the normal personal-override/shared-company policy. The key is supplied only to the child process environment and is never returned to the browser. Each run receives temporary OpenCode config/data directories so OpenCode's normal user-level credential/session storage does not become a cross-account credential store.

Authority

The agent works only inside a workspace path accepted by Warden's configured filesystem root. OpenCode can read/edit files and run commands within that development environment, so agent.run is a high-authority capability. Like Terminal access, commands ultimately execute with the operating-system authority of the account running this Warden instance.

Dogfooding scope

This checkpoint deliberately starts with one model path and foreground task execution. Stop cancels the running request. Agent runs are audited and provider usage is attributed to the Warden account that launched the task. Durable multi-turn sessions, background jobs and broader provider/model selection can be added after the execution loop has survived real development work.

Interaction

Press Enter to run the prompt and Shift+Enter for a new line. While OpenCode is working, Warden shows a continuously moving activity indicator that remains visible across the room as well as a Stop control.

OpenCode stdout recovery

Some OpenCode releases can finish a headless run --format json successfully while failing to emit the final assistant text to stdout. Warden captures the OpenCode session ID during the run; if no assistant text arrives, it exports that same isolated session after completion and recovers the assistant response and usage from the session data instead of displaying an empty success.
