Documentation · Terminal

Terminal

A real Linux PTY over an authenticated WebSocket, shared between the full Terminal page and the Editor's integrated panel.

One live shell

The integrated and expanded terminal views reparent the same terminal DOM/session. Switching views does not reconnect the shell or discard its process state. PTY rows and columns are updated as the panel or browser changes size.

The Editor can request that the shell move to an opened workspace. Warden waits until Bash owns the controlling terminal again before changing directory so it does not inject a cd into an interactive child process.

Authentication and origin checks

The WebSocket upgrade requires an authenticated session, the per-session CSRF token and a matching Origin/Host relationship. ANSI/SGR colour is rendered in the browser without weakening the page CSP with arbitrary inline styles.

Authority

The file root is not a shell sandbox.

--root / WARDEN_FILE_ROOT confines Explorer, Editor and related file APIs. The terminal executes with the Warden process user's ordinary operating-system authority.

Any future roles/capabilities must therefore treat terminal entitlement explicitly. Hiding an administrative button while leaving unrestricted shell access is not a security boundary.
